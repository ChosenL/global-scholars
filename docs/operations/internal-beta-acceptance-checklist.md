# Internal-beta session acceptance checklist

Record the release commit, Preview URL, session date, and operator role without
including student information.

- [ ] Login succeeds on the certified Preview deployment.
- [ ] The expected admin/advisor role is displayed.
- [ ] Only assigned/authorized students are visible.
- [ ] The selected student profile loads without a raw database error.
- [ ] Missing profile fields are presented as missing information, not failure.
- [ ] **Find Matches** reaches a result or an explicit evidence-limited state.
- [ ] Compatibility and evidence completeness are distinguishable.
- [ ] Reasons, unknowns, and known blockers are distinguishable.
- [ ] Intake and scholarship wording describes verified evidence only.
- [ ] **Start Application** preselects the student, university, and program.
- [ ] No application is created before explicit submission.
- [ ] A verified intake can be selected where available.
- [ ] Application creation persists the expected relationships.
- [ ] Status changes persist and appear in history.
- [ ] Advisor assignment persists.
- [ ] Financial fields persist without implying source verification.
- [ ] Disposable manual records are archived when appropriate.
- [ ] Any defect is recorded without PII, credentials, or internal UUIDs.
- [ ] Authorization or unexpected-visibility concerns are escalated immediately.

Session result: **PASS / PASS WITH LIMITATIONS / STOP**
